Clever Sandbox Events API Data Drift Engine

Scheduled, semi-autonomous CSV drift for Clever sandbox districts — so application partners have a live Events API stream to build against instead of a static roster.

Sandbox-only, hard-enforced Fixed weekly cadence CSV-over-SFTP 10% guardrail v0.1.0

github.com/dmcgeary76/event-api-sim

What this is, and why

Clever sandbox districts are set up for application partners to test workflows built on Clever's Events API — but the roster data is static once loaded, so there's no ongoing stream of created / updated / deleted events for a partner to actually observe. This engine keeps a working copy of one sandbox district's CSV roster stack, makes a small, bounded set of realistic edits on a fixed weekly pattern, and re-syncs it over the district's existing SFTP pipeline. Clever's own ingestion diffs the new export against the last one and emits the corresponding Events API records — the engine never calls Clever's API directly.

It deliberately does not have a per-district volume knob or a per-partner change profile: the same cadence and magnitude apply to every configured sandbox district, because partners are told to expect activity on a known, predictable schedule.

The fixed weekly cadence

DayBucket(s)What happens
Mondaysmall_dailyA handful of minor field edits — contact email/phone tweaks, student middle-name/email edits.
Tuesdaysmall_daily + big_studentSmall daily, plus ~4 students moved between sections, a few new guardian contacts, and a couple of contact removals.
Wednesdaysmall_dailySmall daily only.
Thursdaysmall_daily + big_studentSame shape as Tuesday.
Fridaysmall_daily + big_teacherSmall daily, plus co-teacher swaps, a primary-teacher reassignment, and one brand-new teacher added.
Saturday / Sunday—Skipped entirely. No drift runs on weekends.

Big buckets stack on top of the small daily bucket — they never replace it. Magnitudes are hard-coded constants in cadence.py, not configuration.

Safety model

Username allowlist, not hostname

sftp.clever.com is shared infrastructure across many districts, so the hostname proves nothing about whether a target is a sandbox. The SFTP username identifies the district, and the engine hard-fails if the resolved username isn't listed in config/districts.yml.

Data fingerprint, strength-checked + scale sanity

The loaded stack must contain a configured substring (e.g. tulsaschools-replica.org) in its own data — and the fingerprint itself must be ≥8 characters, contain a ., and contain a recognised sandbox marker (replica/sandbox/dev/etc.) before it's trusted as a check at all. Record counts must also stay within 25% of a recorded baseline, checked every run.

10% / 2% deletion guardrail

Clever's real 10% pause-for-review threshold is enforced as a hard block before anything is written. This engine's own stricter 2% ceiling is enforced as a warning. Matched enrollment moves are netted out of the count; unexplained row loss versus the last real push (e.g. a truncated export) is caught.

Dry-run by default

run and seed never open an SFTP connection without an explicit --live flag — no configuration path changes that default. Dry-run output is pruned to the 5 most recent directories per district.

One run per district at a time

An exclusive file lock on state/<district>/.lock is held for the whole of a run; a second overlapping run exits immediately with code 3 instead of racing the first and potentially minting colliding IDs for two different students.

Timezone-aware cadence

Each district's own timezone (default America/Chicago) decides which weekday it is for cadence purposes — never the host machine's or UTC's — so a run near a day boundary can't silently skip a whole day's bucket.

Using the tool

Run locally

python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env   # fill in the SFTP password

drift-engine schedule
drift-engine run          # dry run — no SFTP connection at all
drift-engine run --live   # push for real

Full details in the repository README, the CSV contract in SCHEMA.md, and operational guidance in RUNBOOK.md.

Changelog

Mirrors CHANGELOG.md. Newest first.

2026-07-30

— v0.1.0: Initial release

  • Core engine: schema, models, safety, config, csvstack, cadence, selection, content, seed, guardrail, sftp_push, audit, runner, and cli modules, implementing the full per-run flow from the project brief.
  • Fixed weekly cadence: small daily edits every weekday; big student changes Tue/Thu; big teacher changes Friday; weekends skipped — magnitudes hard-coded, not configurable per district.
  • Six event categories: contacts.created/updated/deleted, sections.updated, users.updated, and teachers.created (added beyond the brief's original five for the Friday new-teacher sub-bucket).
  • Safety model: host + SFTP username allowlist (not hostname), a strength-validated data fingerprint, scale sanity, and an advisory production-marker tripwire — none of which are ever caught or downgraded, and a SafetyViolation is always audited before it propagates.
  • Concurrency: an exclusive per-district file lock prevents two overlapping runs from minting colliding IDs and corrupting each other's edits.
  • Timezone-aware cadence: each district's own configured timezone (default America/Chicago) decides which weekday it is, not the host machine's or UTC's.
  • Guardrail: Clever's real 10% deletion pause threshold enforced as a hard block; this engine's own 2% ceiling enforced as a warning; matched enrollment moves netted out; unexplained row loss versus the last real push detected.
  • CSV integrity: a missing required column is now a hard load error, not a silent blank backfill; saves are all-or-nothing across the whole stack; pushes assert stack completeness before uploading.
  • Content generation fix: generated field "updates" (email, phone, etc.) are now re-rolled until they actually differ from the current value — previously ~62% of predicted contacts.updated events over 26 simulated weeks were silent no-ops.
  • Audit layer: JSON, Markdown, and history.jsonl reports per run, with scoped credential redaction, a preflight check that logs/ is writable before any work happens, and dry-run output capped at the 5 most recent directories per district.
  • Three schema additions: a Middle name column on students.csv, a Teacher 2 id column on sections.csv, and the entire contacts.csv file — all spec-optional, added because the real export had no mutable surface for three of the six event categories required.
  • Known limitations, documented not hidden: teacher population has no attrition (breaches scale-sanity in ~7 years); whether Clever emits events for a column going absent→empty on first sync is unconfirmed; eventing_verified is still false; real paramiko transport is code-reviewed but never executed in this build environment.
  • Docs: README, SCHEMA.md, RUNBOOK.md, this changelog, and this project page.
